# 2.1.5 Физическая модель базы данных

Логическая модель предметной области (п. 2.1.4, рис. 2.6) описывает сущности и связи на уровне предметной области. Физическая модель отражает реализацию хранения данных в СУБД PostgreSQL: имена таблиц, столбцов, типы данных, первичные и внешние ключи, уникальные ограничения и индексы. Схема согласована с файлом `prisma/schema.prisma` и применяется через миграции Prisma.

В физической модели выделены шесть таблиц:

- **User** — учётные записи пользователей и профиль врача;
- **DoctorSchedule** — недельное расписание слотов приёма;
- **Appointment** — записи на приём и их статусы;
- **DoctorDiploma** — метаданные дипломов врача и путь к PDF;
- **PatientDocument** — документы пациента, загруженные менеджером;
- **PatientNote** — врачебные заметки по пациенту.

Связи между таблицами реализованы внешними ключами с каскадным удалением (`ON DELETE CASCADE`): при удалении пользователя удаляются связанные записи расписания, приёмов, документов и заметок, если они относятся к этому пользователю.

Для полей-перечислений в PostgreSQL используются типы `Role`, `Weekday`, `AppointmentStatus`, `PatientDocumentType`. Поле `doctorSymptoms` в таблице `User` имеет тип `JSONB` и хранит данные для подбора специалиста.
